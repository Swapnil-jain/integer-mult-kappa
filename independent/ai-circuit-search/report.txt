INTEGER MULTIPLICATION: EXPERIMENT AND CONDITIONAL CANDIDATE
8 October 2026

I found a circuit variant with a larger certified finite exponent saving than
both the linked Jain repository and the pinned community reference. The
candidate is kappa = 3955279/100000000000 = 0.00003955279 in the proposed bound

    T(n) = O(n (log n)^(1-kappa)).

The finite calculations and changed circuit checks pass. This is a conditional
research candidate, not an independently established new multiplication theorem
or a claim of worldwide priority. It inherits the original OpenAI framework and
the community's general physical, analytic, tape and exact-recovery arguments.

Comparison of exponent savings (larger kappa is better):

  OpenAI original claim:       2^-182
  Jain pinned round six:      0.00003666565558019
  Community pinned PR39:      0.00003886675852
  This candidate:             0.00003955279

The candidate increases kappa by 7.8742200954% over Jain and 1.7650853998% over
the community reference. These percentages concern kappa, not execution time.
The corresponding exponent on log n is 0.99996044721, not an exponent on n.

What changed, in ordinary language

The published construction needs many related sums. Think of each partial sum
as occupying a temporary box. A plan with fewer additions can still be costly
if it needs many separate boxes. I rearranged how sums are built so that more
boxes can safely be reused later. This does more additions but lowers the
combined storage and recursive cost that controls this particular bound.

Specifically, in the community's generic 23-dimensional first-axis circuit:

                                 Original       Candidate
  Additions                         34,764          36,328
  Designated outputs                 5,336           5,336
  Valid carrier matches              1,324           4,044
  Roles = additions+outputs-matches  38,776          37,620

The ordinary total function becomes a left-associated running sum, corresponding
to split=n-1 in its recursive implementation. The leave-one-out sums use a
binary tree split at the largest power of two strictly smaller than its length;
each leaf receives the sum of all sibling subtrees on its path. These siblings
partition exactly the other leaves, so the omitted-input sums are exact.
The weighted pair recursion still stops at size two. The global point ordering,
second-axis fixed basis, copied-center costs and data profile are retained.

The bit network has m=575, W=185523129 and complete rank mass 106673952275.
The old W was 188181929. All 27 child widths and their counts are in
certificate.json. The 25-dimensional fixed profile is inherited, not regenerated
by our audit. The unchanged complex network and its charge remain included.

How the search worked

There were 652 recorded configuration evaluations in eight batches:

  Dimension and point-order sweep:          90
  Sum-tree and stopping-size sweep:        140
  Grouping, exclusion and join variants:   90
  Smaller recursion bases:                 48
  Dimension refinement:                   128
  Reusing existing partial sums:           54
  Deterministic stochastic tree search:    57
  Community construction with matching:    45

This is an evaluation count, not 652 distinct algorithms: some configurations
duplicate the same circuit, and some batches overlap. The stochastic search
used seed 817362. No claimed global optimality follows from these searches.

Fast floating-point scores were used only to select candidates. Each reported
winner was then checked using exact integers and rational bounds. The decisive
gain appeared after including the community's carrier-matching machinery in
the objective: minimizing additions alone was the wrong target.

The earlier Jain-only tree change gives kappa=0.000036675644497175837593, an
increase of only 0.0272432521% over Jain. Sharpening the old community arithmetic
alone gives only a roughly 3e-8 percent increase. Both are retained in the
certificate for comparison; the main result above changes the actual circuit.

What Python proves here

The new community audit independently reconstructs all 38,099 active scalar
nodes and all 5,336 output sums. It interprets the generated labels as 26,695
explicit rational subspaces using integer bases. It checks 72,656 gate
inclusions and all 4,044 carrier-matching inclusions, unique matched endpoints,
and an acyclic combined event order. It recomputes the entire transition
histogram and reconstructs the full child profile.

For each common center c, the audit proves sum(x)=3*x_c on every label basis
vector. With H=I-J/9 this implies x^T H x=sum_(i!=c) x_i^2. This is positive
definite on that common-center space: if the right side vanishes, the defining
relation also forces x_c=0. The basis vectors have disjoint nonzero free
component coordinates, which proves their independence. Source membership,
gate nesting and output orthogonality are exact integer identities.

Under the inherited partial-swap compiler, nested nondegenerate subspaces
give projector differences with the checked dimension changes. Each validated
carrier match removes one role and changes the transition histogram by

  -z^(h-r_u) -z^r_y -z^(r_w-r_y) +z^(r_w-r_u),

where y is the reused operand and W_y subset W_u subset W_w. The rank mass
therefore drops by h per match. The common-basis argument remains applicable
conditionally: the changed first-axis projectors add only finitely many
ordinary-profile nonvanishing conditions on the same GL23 family. The
community geometry proof's fixed second-axis contractions are unchanged.
This uses the published general lemmas; it is not a fresh formalization of them.

For the numerical part define

  F(a) = (1/W) sum_w count_w * (w/m)^(1-a).

Every width is positive and smaller than m. Thus F is strictly increasing.
The verifier proves F(a_bit)<1 at

  a_bit = 39554359/10^12 = 0.000039554359.

It also brackets the exact root between adjacent multiples of 10^-24:

  0.000039554359469713356360
  0.000039554359469713356361.

To avoid floating-point assumptions, log(x) is reduced to log(y)+k log(2),
1<=y<=2, and bounded using z=(y-1)/(y+1):

  2 sum_(j=0..71) z^(2j+1)/(2j+1)
  <= log(y)
  <= that sum + 2*z^145/(145*(1-z^2)).

All operations are rational, including outward rounding. Exponentials use the
degree-12 positive Taylor polynomial P12(u) and the bound

  P12(u) <= exp(u) <= P12(u)+(u^13/13!)/(1-u/14),  0<=u<14.

Applied term by term to F, these bounds establish the strict inequalities.
The unchanged complex saving is 717/10^7. The inherited balanced assembly
passes all 47 strict constraints at h=10^-12 and kappa=3955279/10^11, with the
updated bit role volume. Thus the numerical saving survives the assembly.

For any fixed profile in this assembly, the best possible limiting saving is
at most a/(1+a): maximize min(1-epsilon,epsilon*a) by balancing its two terms.
This is a ceiling for parameter tuning of that profile, not a lower bound for
all multiplication algorithms. Larger improvements need a better profile or a
different mathematical assembly.

Validation and limits

The unchanged community first-axis producer was regenerated and matched its
pinned histogram exactly before changing it. The new candidate was regenerated
with the upstream C++ matching helpers and separately audited in Python.
The portable saved-certificate audit needs Python only. The full checks also
reproduce Jain's candidate circuit, pass the seven adversarial arithmetic tests,
and pass the three inherited round-six tests. Corrupted supports, invalid
vectors, overstated savings, and stale assembly inputs are rejected by the
relevant checks. Lean was not run here.

Python has verified finite algebra and inequalities; it has not implemented
or formally proved the complete all-input finite-tape multiplier. In particular,
the fixed25 profile/CRT certificate, simultaneous physical basis and copied
stream transfer, arbitrary dirty scratch restoration, native routing, analytic
precision, eligible-prime setup, and exact recovery rely on the cited upstream
arguments. These dependencies need mathematical review before treating this
candidate as a new unconditional complexity result.

No multiplication speed benchmark or practical speedup is claimed. Enormous
constants and eventual thresholds remain. A larger kappa changes asymptotic
growth, but a 1.765% increase in this tiny saving is not 1.765% faster software.

How this fits the original complexity question

For n-bit inputs, ordinary long multiplication uses O(n^2) bit operations;
Karatsuba uses O(n^log_2(3)), approximately O(n^1.585). The established
Harvey-van der Hoeven result gives O(n log n). The OpenAI release announced on
6 October 2026 includes a preprint dated 23 September claiming
O(n (log n)^(1-2^-182)) in the fixed finite-alphabet multitape model. If its
proof is sound, crossing below n log n is a major theoretical change even
though its direct exponent saving is extremely small. The exact optimal
complexity is not established by this experiment; the basic input/output
lower bound is linear.

This illustrates one way such discoveries can be made: mathematical arguments
reduce an infinite family of input sizes to a finite network and inequalities;
code searches the finite design space; exact certificates replace approximate
scores; then mathematical transfer arguments connect the certificate back to
the all-size algorithm. Searching examples alone would not prove an asymptotic
bound. I cannot infer the private discovery process behind OpenAI's paper from
its published statement; the account above describes this experiment.
